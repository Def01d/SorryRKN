# Изменения

[← Главная](README.md) · [Все релизы](https://github.com/Def01d/SorryRKN/releases)

Android и Windows имеют независимые номера версий.

## Android 0.10.0

[Релиз](https://github.com/Def01d/SorryRKN/releases/tag/v0.10.0) · [APK](https://raw.githubusercontent.com/Def01d/SorryRKN/v0.10.0/SorryRKN-0.10.0.apk)

- Telegram: исправлены отказы параллельных TCP-подключений к одному DC. Холодный или исчерпанный пул WSS теперь ограниченно ждёт готовое соединение. Воспроизведён прежний сбой: семь из восьми одновременно пришедших клиентов получали отказ при работающем сервере.
- Официальные WSS-адреса DC1–5 разрешаются через проверенный DoH; альтернативные адреса проверяются до передачи MTProto-данных, лишние сокеты закрываются. CDN203 использует отдельный native TCP-маршрут, без неподтверждённой подмены на обычный DC2.
- TLS/WSS Telegram проходит через локальный ByeDPI с проверкой сертификата и имени. Общий таймаут охватывает TCP, SOCKS, TLS и Upgrade. Публичные CF-прокси и HTTP2-реле отключены для сохранения своего IP.
- ChatGPT, другие нейросети и пользовательские домены теперь используют обычный DNS и локальный обход DPI. Раньше нейросети уходили на Comss-адреса без обработки DPI. Добавлены узкие правила для зависимостей ChatGPT.
- Публичная проверка ChatGPT различает транспортную ошибку, проверку в браузере, отказ сервера и региональный отказ; результат показан под переключателем. Она не подтверждает доступ к аккаунту и не перезапускает соединения.
- «Мои ресурсы»: записи сохранены, первый список переименован в «Обход DPI · ваш IP» и использует прямой маршрут. Прямые исключения сохраняют приоритет. Автопроверка APK при каждом открытии сохранена.

**Изменение режима:** Android работает со своим IP. Серверный запрет по стране IP или аккаунта локальный обход DPI не снимает; доступ к ChatGPT в РФ этим релизом не гарантируется. Windows остаётся 1.1.0 с прежним поведением. [Проверки](docs/VALIDATION-ANDROID.md).

## Android 0.9.4

[Релиз](https://github.com/Def01d/SorryRKN/releases/tag/v0.9.4) · [APK](https://raw.githubusercontent.com/Def01d/SorryRKN/v0.9.4/SorryRKN-0.9.4.apk)

- Исправлен выбор адреса DNS-профиля: ChatGPT и другие выбранные ресурсы могут использовать запасной IPv4-адрес при ошибке подключения, отсутствии начального TLS-ответа или fatal TLS alert. Раньше использовался только первый адрес ответа.
- При наличии запасного адреса первая попытка ограничена тремя секундами; сбойный адрес на 90 секунд получает меньший приоритет. Повторяется только начальное TLS-приветствие, пользовательские HTTP-запросы и 0-RTT данные повторно не отправляются. Проверка сертификата и приоритет прямых исключений сохраняются.
- APK проверяется в фоне при каждом открытии или возвращении в приложение. Убран шестичасовой интервал; запрос обновления не использует HTTP-кеш. Если экран пересоздан во время проверки, предложение получает новый экран, без дублирования запроса.
- В диагностику добавлены число попыток и переходов на запасной адрес, стадия последней попытки и адрес DNS-профиля. Telegram-транспорт 0.9.3 сохраняется.

Исправление проверено на локальном отказе первого адреса и работающем втором. Доступность ChatGPT на конкретном операторском маршруте зависит от сети и провайдера DNS-профиля. [Подробности проверок](docs/VALIDATION-ANDROID.md).

## Android 0.9.3

[Релиз](https://github.com/Def01d/SorryRKN/releases/tag/v0.9.3) · [APK](https://raw.githubusercontent.com/Def01d/SorryRKN/v0.9.3/SorryRKN-0.9.3.apk)

- Восстановление зависших медиа-запросов Telegram: после 60 секунд без входящих данных освобождается соответствующая сессия, чтобы клиент мог повторить загрузку. При поступлении частей большого кадра ожидание продлевается; простой без запросов и задержка чтения на стороне клиента сохраняют канал.
- Проверка применяется к медиа WebSocket, HTTP2 и резервному TCP. Восстановление конкретной сессии сохраняет работающий движок и соседние соединения.
- После зависания основного медиа-маршрута удаляются его неиспользуемые сокеты; следующая попытка может использовать существующий резервный маршрут. Для зависшего HTTP2-маршрута вводится короткая пауза при выборе новых каналов, существующие каналы сохраняются.
- Ограничено ожидание закрытия TLS/WebSocket. Исправлено освобождение сокета после серверного Close.
- Диагностика содержит счётчики зависаний, сбросов медиа-пула и активные медиа-сессии с временем ожидания данных. Ping-проверки из 0.9.1 не возвращались.

Это восстановление после наблюдаемого отсутствия данных, а не гарантия доступности маршрута. Если проблема повторяется, сохраните диагностику до ручного выключения программы.

## Android 0.9.2

[Релиз](https://github.com/Def01d/SorryRKN/releases/tag/v0.9.2) · [APK](https://raw.githubusercontent.com/Def01d/SorryRKN/v0.9.2/SorryRKN-0.9.2.apk)

- Исправлена регрессия Telegram в 0.9.1: восстановлен транспорт версии 0.9.0 без принудительных ping-проверок активных и готовых соединений. Рабочий канал больше не закрывается из-за отсутствия pong.
- Неудачные фоновые проверки YouTube/Discord записываются в диагностику и больше не запускают автоматический переподбор с разрывом всех подключений. Переподбор доступен вручную в меню.
- Сохранены быстрый запуск с отдельными методами для Wi-Fi и мобильной сети, DNS-кеш и пользовательские правила. Установите поверх 0.9.1: настройки и Telegram-прокси сохранятся.

## Android 0.9.1

**Заменена версией 0.9.2 из-за регрессии переподключений Telegram.** Описание ниже относится к исторической сборке.

- Быстрый повторный запуск с сохранёнными методами для Wi-Fi и мобильного интернета; проверка выполняется в фоне. Общие обновления списков и Telegram-доменов больше не сбрасывают приоритет метода.
- Пересоздание соединений при смене физической сети или её адресов, включая ручной метод и режим только Telegram.
- Проверка живости Telegram WebSocket/HTTP2 и закрытие зависших каналов для переподключения клиента; сокращены длительные паузы повторных попыток.
- Восстановление остановившегося сетевого движка с задержкой повторных попыток.
- Повторный запрос к единственному DNS-провайдеру при временном сбое; ограниченный кеш положительных ответов с учётом TTL, объединение одинаковых запросов и повторное использование проверяющего сертификаты TLS-контекста для DNS/проверок.

Первый подбор, ручной «Подобрать заново» и подбор после подтверждённого отказа метода по-прежнему проверяют сеть. Доступность внешних сервисов зависит от оператора и DNS-провайдера.

## Android 0.9.0 и Windows 1.1.0

[Android 0.9.0](https://github.com/Def01d/SorryRKN/releases/tag/v0.9.0) · [Windows 1.1.0](https://github.com/Def01d/SorryRKN/releases/tag/windows-v1.1.0)

- Меню **«Мои ресурсы»**: ручные домены DNS-профиля и исключения с прямым подключением.
- Приём доменов и HTTP/HTTPS-ссылок, нормализация IDN, учёт поддоменов и проверка ввода; до 256 записей в каждом списке.
- Прямые правила имеют приоритет над пользовательским и встроенным DNS-профилем и обходом DPI.
- Пользовательские списки хранятся отдельно и сохраняются при обновлении данных GitHub и программы.
- Пользовательские DNS-домены работают при включении соединения даже с выключенным переключателем встроенных нейросетей.
- Android: исключения учитываются при выборе DNS, TCP-маршрута и пропуске UDP/443 для адресов, полученных из обычного DNS.
- Windows: правило без desync применяется перед профилями DPI; DNS-профиль и прямые исключения учитывают один набор правил.
- Исправлено отображение состояния Android: активный пользовательский DNS-профиль учитывается отдельно от результатов подбора DPI.

Применение — при следующем включении. DNS-профиль по-прежнему зависит от поддержки маршрута Comss и не выдаёт зарубежный IP произвольному сайту.

## Windows 1.0.0

[Релиз](https://github.com/Def01d/SorryRKN/releases/tag/windows-v1.0.0) · [Установщик](https://raw.githubusercontent.com/Def01d/SorryRKN/windows-v1.0.0/windows/SorryRKN-Windows-1.0.0-Setup.exe) · [Переносная версия](https://raw.githubusercontent.com/Def01d/SorryRKN/windows-v1.0.0/windows/SorryRKN-Windows-1.0.0.zip)

- Первая Windows-версия: нативный интерфейс в чёрно-бело-серых тонах, установщик и переносной ZIP.
- Оригинальный zapret/winws и WinDivert, 22 совместимых профиля, быстрый и расширенный автоподбор.
- Встроенный Telegram MTProto → WebSocket/HTTP2 прокси; Python и криптография включены.
- Выборочный Comss DNS для ChatGPT, Claude и Gemini, отдельное правило DPI для Instagram.
- Управление из системного трея, работа после закрытия окна и завершение собственных процессов при выходе.
- Хранение секрета Telegram с Windows DPAPI.
- Автообновление совместимых данных GitHub; отдельный источник обновления Windows с проверкой размера и SHA-256 установщика.
- Опубликованы исходники Windows и инструкция по сборке.

## Android 0.8.0

[Релиз](https://github.com/Def01d/SorryRKN/releases/tag/v0.8.0) · [APK](https://raw.githubusercontent.com/Def01d/SorryRKN/v0.8.0/SorryRKN-0.8.0.apk)

- Приложение переименовано из GrayBridge в SorryRKN; обновлены иконка, кнопка подключения и переключатели.
- Ускорена передача данных для AES-CTR между Java и Python: пакетное копирование вместо побайтовых JNI-вызовов.
- Пул готовых Telegram-соединений увеличен с 2 до 4.
- Добавлены счётчики Telegram в диагностику.
- Добавлены проверка новых APK при запуске и пункт **«Обновить приложение»**.
- Перед установкой проверяются размер, SHA-256, пакет, версия и подпись.
- Пакет `dev.graybridge` и подпись сохранены для обновления поверх GrayBridge 0.7.

Методы YouTube, Discord, Instagram и профиль Gemini в 0.8 не менялись. Изменения Telegram уменьшают затраты обработки в программе; скорость на конкретной сети требует отдельной проверки.
