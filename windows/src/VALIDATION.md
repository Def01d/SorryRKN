# Проверки Windows 1.9.1

- **Регистронезависимые исключения и корпоративный DNS:** `TestConfigForExcludedApps` проверяет `process_path_regex` (`(?i)`), перенос TUN на `198.19.254.1/30`, исключение `172.16.0.0/12`, правила `direct_domains` (с `sniff`) и цепочку fallback при `NXDOMAIN`; `TestPinnedEngineAcceptsSupportedProfiles` проверяет итоговые профили через `sing-box.exe check -c stdin` во всех протоколах.
- **Живая WinTUN-проверка (`TestIsolatedTUNProcessExclusion`):** на изолированном Windows-раннере CI проверяется, что без исключения трафик тестового бинарника идёт через `SorryRKN-Tunnel` к контрольному узлу, а после добавления в исключения со смешанным регистром имени `.exe` — уходит напрямую мимо VPN-туннеля.

Предыдущие результаты Windows 1.9.0 и 1.8.0 сохранены ниже.

## Версия 1.9.0

- **Юнит- и конфиг-тесты:** `TestExcludedAppsNormalizationAndConfigRoundtrip` (нормализация имён `.exe` и путей, лимиты, сохранение `config.json` без потери `protected_secret`), `TestUDPSourcePort` (разбор исходного порта UDP в IPv4/IPv6), `TestConfigForExcludedApps` и расширенный `TestPinnedEngineAcceptsSupportedProfiles` (валидация реальным `sing-box.exe check -c stdin` профилей как без исключений, так и с `process_name` / `direct` / `direct-dns`).
- **Нативная UI-проверка в CI (`validate.ps1`):** открытие окна `SorryRKNApps` («Исключения приложений»), проверка непустого списка запущенных процессов ПК (`GetRunningApps` / `CreateToolhelp32Snapshot`), добавление `.exe`, снятие скриншота `windows-apps.png`, сохранение в `config.json` без изменения `protected_secret`.
- **Ограничения локального режима:** сопоставление процессов SmartDNS использует `GetExtendedUdpTable` для UDP/53; пакетный движок `winws.exe` не фильтрует процессы по PID, поэтому исключение отдельных доменов от DPI по-прежнему настраивается в «Мои ресурсы → Напрямую».

## Версия 1.8.0

В CI сборка пакета, создание туннеля и установка выполняются на изолированных машинах. Go-тесты с детектором гонок (`internal/mirage`, `internal/selfhost`, `internal/tunnel`) проверяют активную HTML-заглушку при неавторизованном зонде или повторе, отклонение неверного TLS pin, конкурентные TCP и UDP ASSOCIATE потоки, бесшовную ротацию несущего соединения, блокировку SSRF на приватные адреса и разбор ответов `SRKN1`.

Изолированный VM-скрипт (`integration-mirage.sh`) на GitHub Actions Ubuntu дополнительно проверяет реальный systemd-сервис `sorryrkn-mirage.service`, клиент `sorryrkn-mirage client` через DNS/DNAT-стенд, установку `hy2-on`, `grpc-on`, `ss2022-on`, аутентифицированный публичный SOCKS5 (`socks-pub-on`), отказ неаутентифицированным клиентам, статус флота (`fleet-status`) и чистое удаление `purge-all`. Проверка эффективности против конкретных провайдеров связи не выполняется.

## Версия 1.7.0

В CI сборка пакета, создание туннеля и установка выполняются на изолированных машинах. Проверка интерфейса импортирует узел с тестовыми данными и запускает приложение дважды подряд, чтобы обнаружить возврат шестичасового ограничения проверки обновлений. Отдельные проверки передают данные через VLESS REALITY и через HTTPS CONNECT, а также проверяют правильный и неправильный пароль SOCKS5. Пакет для обычного выпуска берётся из успешно завершившейся сборки.

Дополнительный тест передаёт HTTPS, WebSocket Hello и 100 UDP-пакетов размером 64, 160, 1000 и 1300 байт через VLESS внутри Chromium HTTPS CONNECT. Проверка VPS передаёт те же UDP-датаграммы через настоящий Caddy, закрытый SOCKS-шлюз и loopback VLESS. Проверки аккаунта Discord и голосового звонка не выполняются.

## Версия 1.4.0

Исходники включают маршруты DNS по сервисам, явный автоматический резерв, кеш проверок по сети, проверку подписанных данных и резервирование настроек.

- Go-тесты и vet прошли; проверяются отдельные рабочие DNS, приоритет прямых исключений, закрепление ручного выбора, две ошибки перед переключением, cooldown, срок кеша и подписи, изменение payload/ключа, ограничение TTL клиентских ответов и восстановление настроек без смены секрета.
- GitHub Actions собирает Setup и ZIP из исходников, запускает Go и 11 тестов встроенного Python runtime. Отдельная изолированная Windows-машина проверяет WinDivert, DNS-перехват, запуск/остановку winws, GUI, восемь списков маршрутов, сохранение настроек и секрета, установку и удаление.
- Экспорт/восстановление ключа данных проверяются на временных ключах: тот же открытый ключ после восстановления и отказ при неправильном пароле. Ключ выпуска в этих тестах не используется.
- Живое сравнение семи профилей и восьми сервисов выполняется отдельно без драйвера. Это публичные HTTPS-ответы; аккаунты, генерация, воспроизведение видео, звонки и все операторы не подтверждены.

Установщик/UAC/WinDivert на компьютере владельца не запускались. Нативные проверки выполняются только в явно выделенной изолированной машине; `windows/validate.ps1` требует `-IsolatedTestMachine`.

Окончательные ссылки на CI, контрольные суммы пакетов и публичный канал обновлений публикуются в отчёте релиза. Исторические результаты Windows 1.2.0 доступны в Git-теге `windows-v1.2.0` и не считаются повторной проверкой этой версии.
