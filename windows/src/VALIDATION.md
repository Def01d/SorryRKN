# Проверка Windows 1.2.0

Локальные проверки 9–10 октября 2026 года, переносимая сборка проверена 10 октября в 11:18 МСК (08:18 UTC), Windows x64, Go 1.26.3 и встроенный Python 3.12. Стабильная публикация: [windows-v1.2.0](https://github.com/Def01d/SorryRKN/releases/tag/windows-v1.2.0). Результаты относятся к доступной сети этого компьютера.

Перед предварительной публикацией пакет пересобран после интеграции `main` на базе `dc2141f`: сохранён режим подготовки runtime `-RuntimeOnly`, ресурсы EXE версии 1.2.0 генерируются закреплённым `go-winres v0.3.3`. Повторно выполнены сборка, Go-тесты, core/platform vet и 11 Python-тестов. Код сетевых механизмов и runtime не изменились; сетевые результаты ниже относятся к прогону 08:18 UTC и повторно не измерялись. WinDivert и UAC при пересборке не запускались.

## Исправленные причины

- В существующем telegram.log были сотни ошибок CF H2 `/api HTTP 404`, ноль native TCP-подключений и статус, основанный только на открытом локальном порту. Новый путь выбирается по ответу MTProto; зависающий H2 исключён из активного пути.
- DNS-профиль зависел от одного адреса Comss. Системный DNS также не разрешал www.youtube.com; защищённое разрешение восстановило контрольный HTTPS-запрос.
- Среди адресов ChatGPT, возвращаемых Comss DNS, встречаются ответы с проверкой браузера. Для `chatgpt.com` добавлен выбор адреса по двум независимым TLS-запросам к публичному `/api/auth/providers`: нужны HTTP 200 и JSON с провайдером OpenAI OAuth. Проверяются сертификат, имя сервера и Host. Параллельный выбор ограничен тремя секундами; успешный адрес сохраняется на 120 секунд и используется в реальном A-ответе DNS с TTL до 30 секунд. При отсутствии подтверждённого адреса сохраняются все исходные адреса, но TTL ограничивается 15 секундами; неуспешный подбор повторяется не чаще чем через 15 секунд. Прямые исключения сохраняются; запросы пользователя не читаются и не повторяются.
- Проверки состояния и обработчик перехваченного DNS используют один активный экземпляр SmartDNS и общий выбранный маршрут. Независимый DNS-кэш для фоновой диагностики удалён; после остановки DNS успешный статус не подставляется.
- Быстрый подбор не переходил к остальным профилям автоматически; добавлен переход, включая случай отсутствующих файлов последнего быстрого профиля.

## Выполнено

- `go test ./...` — успешно на окончательном коде. Проверяются резервирование DNS, TTL, отмена, разделение AI/public DNS, исключения, поддельные HTTP-ответы, свежесть Telegram health и расширение автоподбора. Новые проверки выбора ChatGPT покрывают недоверенный TLS-сертификат, Host/SNI, неверный OAuth JSON, challenge-ответ, нестабильный адрес, кэш, отмену, независимость других DNS-запросов, общий маршрут диагностики и приложений, короткий TTL без удаления неподтверждённых адресов и сохранение EDNS. `go vet ./internal/core ./internal/platform` — успешно.
- 11 Python-тестов: все три framing-протокола, продолжение шифра, media DC, неверный секрет/nonce, зависающий маршрут, отсутствие повторной передачи пользовательского запроса, атомарный отчёт и обновление сохранённого пула реле.
- `scripts/check-telegram.py` со встроенным Python и runtime окончательного пакета — **10/10** действительных ответов через локальный прокси: DC1–5, обычные и media-соединения. Задержки 78–734 мс. Проверены nonce, TL-структура ответа, закрытие процесса и освобождение порта. Использованы временный секрет и свободный порт; настройки установленного приложения не менялись.
- Окончательный `check-network.exe` — через защищённый DNS прошли YouTube HTTPS 204 и Discord API/CDN/WebSocket Hello; Instagram вернул ожидаемую страницу. **ChatGPT Authentication API прошёл через автоматически выбранный `157.22.177.90`: два подтверждения маршрута и отдельный диагностический запрос.** Прямое соединение получило проверку браузера. Это один прогон после исправлений общего DNS-кэша и TTL, без повторов до успешного результата.
- Нестабильность ChatGPT остаётся наблюдаемым ограничением: в 08:10 UTC проверка через Comss не прошла, а до усиления проверки `95.81.102.20` получил challenge после успешного выбора. Более ранний запуск через `157.22.177.90` был успешным. Все эти отчёты сохранены; постоянная доступность внешнего маршрута не подтверждена.
- В проверке 9 октября в браузере открылась страница ChatGPT с формой ввода и входом в аккаунт. Сообщения не отправлялись; работа аккаунта и генерация ответов не подтверждены.
- `scripts/build.ps1` собрал переносимый ZIP с `SorryRKN.exe`, `check-network.exe`, встроенным Python и runtime. Для стабильного выпуска добавлен установщик NSIS 3.13 из того же очищенного каталога пакета; подробности ниже.

Отчёты окончательного пакета: `dist/telegram-package-check.json` и `dist/network-package-check.json`. Предыдущие результаты сохранены в `dist/chatgpt-route-preference.json`, `dist/network-package-initial-check.json` и `dist/network-package-pre-shared-resolver.json`. Они не содержат Telegram-секретов, токенов аккаунта или переписки. Рядом с распространяемым ZIP отчёты имеют префикс `windows-`.

## Установщик и обновление до стабильной 1.2.0

- `scripts/setup-nsis.ps1` получает официальный portable NSIS 3.13 и проверяет SHA-256 `ba63dffc4410ee89193e1cb5a41989991bd77c61068da17e3156d136b7b0b3d8`. Компилятор работает без установки в систему; сборка использует UTF-8 и `/NOCONFIG`.
- `SorryRKN-Windows-1.2.0-Setup.exe` собран из очищенного `dist/package/SorryRKN`. Проверены версия 1.2.0, целостность NSIS/LZMA-архива и SHA-256 каждого распакованного файла относительно переносного пакета. Установщик не запускался. Его стандартный NSIS loader — x86 Unicode; программа внутри — x64, а `.onInit` отклоняет 32-битную Windows.
- По коду установщика повторно используется `HKLM\Software\SorryRKN\InstallPath` в 64-битном представлении реестра. Проверка mutex просит закрыть запущенное приложение. Обновление заменяет программу, runtime и лицензии, не обращаясь к `%LOCALAPPDATA%\SorryRKN`; удаление программы тоже сохраняет пользовательские настройки и DPAPI-секрет. Это статическая проверка сценария, не фактическая установка поверх 1.1.0.
- Действующий updater принимает Windows EXE только с HTTPS-адреса `raw.githubusercontent.com/Def01d/SorryRKN/windows-v…`, проверяет размер, SHA-256 и сигнатуру `MZ`, затем запускает установщик после согласия пользователя. Ссылку обычного GitHub release asset старый updater не принимает. Для 1.1.0 (`10100`) стабильный код `10200` новее; предложение появляется при следующей проверке обновлений. У предварительной 1.2.0-rc.1 уже тот же код `10200`, поэтому автоматического предложения между ними нет.
- Отчёт упаковки — `windows-installer-validation.json`, контрольные суммы — `SHA256SUMS-Windows.txt`. Нативная установка, удаление, UAC и драйвер остаются непроверенными на этом компьютере.

## Не подтверждено

- Нативный тест WinDivert не запущен: запрос повышения прав Windows отменён. Настройки установленного приложения не изменялись. Драйвер, GUI и полный маршрут через перехват требуют проверки с правами администратора.
- `go test -race` не удалось собрать доступным Zig: отсутствует подходящая библиотека импорта Windows для race runtime. Обычные тесты проходят. `go vet ./internal/core ./internal/platform` проходит; полный `go vet ./...` отмечает существующее преобразование Win32 callback uintptr в unsafe.Pointer в GUI.
- ChatGPT остаётся зависимым от доступности внешнего маршрута и проверки браузера. Автоматический выбор не гарантирует работу аккаунта или ответа на сообщение; эта проблема не объявляется полностью устранённой.
- Не проверены воспроизведение YouTube, звонки, вход в аккаунты и ответы ChatGPT. HTTP/API/MTProto-тесты не заменяют эти сценарии.
- Собственный DoH браузера и TCP DNS обходят UDP/53-перехват. Полная блокировка IP или региональный отказ требует доступного внешнего VPN/прокси. Работа у всех операторов не заявляется.
- Android исправляется отдельно по предоставленному владельцем архиву исходников. Результаты Windows не подтверждают работу Android VPN; совместимое обновление Android требует подписи существующим ключом владельца.

## Повторение

Из каталога исходников:

```powershell
go test ./...
go vet ./internal/core ./internal/platform
runtime\python\python.exe -m unittest discover -s runtime\app -p 'test_*.py' -v
runtime\python\python.exe scripts\check-telegram.py --output dist\telegram-check.json
go run ./cmd/check-network -output dist/network-check.json
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
.\dist\package\SorryRKN\check-network.exe -output dist/network-package-check.json
.\dist\package\SorryRKN\runtime\python\python.exe scripts\check-telegram.py --runtime dist/package/SorryRKN/runtime --output dist/telegram-package-check.json
```

Из повышенного PowerShell можно выполнить изолированный драйверный тест:

```powershell
.\dist\package\SorryRKN\SorryRKN.exe --self-test "$PWD\dist\native-selftest"
Get-Content .\dist\native-selftest\self-test.json
```
