# Android 0.12.0: передача на подпись

Историческое поручение; последний готовый вход: [Android 0.13.0](ANDROID-0.13.0-SIGNING.md).

Исходники и проверки готовы. Основной канал Android остаётся на подписанной 0.11.0, пока недоступен исходный сервис хранения ключа. Неподписанный APK и пакет `.dev` нельзя публиковать в `update.json`.

## Точный входной файл

- Репозиторий GitHub: `Def01d/SorryRKN`.
- [Git blob неподписанного APK](https://api.github.com/repos/Def01d/SorryRKN/git/blobs/5ee71bfbc7362a649ff34647da77be759c980dde). Поле `content` закодировано base64.
- Git blob SHA-1: `5ee71bfbc7362a649ff34647da77be759c980dde`.
- Размер: **20 071 239 байт**.
- SHA-256: `38b529a1cec1c8db7bc4992eb524e4730b805c4951f226fa4ef4ce86f55714c5`.
- Пакет: `dev.graybridge`; версия `0.12.0`; `versionCode=19`; `minSdk=26`.

Файл собран до последующих изменений документации. Код приложения не менялся. Не пересобирать и не изменять исходные ZIP entries при подписи.

## Требуемый результат

Подписать исходным ключом прежних обычных APK. SHA-256 сертификата должен быть ровно `854ef7e3cbfdb5fc624bc3ec7b7d9e17780b709bac7fb85b77dbf4ea0acf2ef4`. Это публичный отпечаток сертификата, а не ключ. Сам ключ и пароли остаются в исходной среде; их нельзя выводить, коммитить или передавать.

Имя результата: `SorryRKN-0.12.0.apk`. Проверить `apksigner verify --verbose --print-certs`, `zipalign -c -P 16 -v 4`, пакет и версию, а также побайтную неизменность содержимого исходных ZIP entries. При доступном эмуляторе проверить обновление с 0.11.0: UID, настройки, выбранный DNS и Telegram-секрет сохраняются; VPN и аккаунты не запускать. Использовать только синтетические настройки.

Передать подписанный APK и очищенный отчёт как Git blobs в тот же репозиторий. Сообщить blob SHA обоих файлов, размер и SHA-256 готового APK. В отчёте не должно быть ключа, паролей, токенов, пользовательских настроек или личных путей.

Исполнитель подписи не меняет основную ветку, теги, релизы и каналы обновлений. Публикующий исполнитель проверяет результат независимо, создаёт **обычный** релиз `v0.12.0`, проверяет точный APK по неизменяемому тегу и только затем обновляет `update.json`. Существующие установщики сверяют пакет, версию и прежнюю подпись; обходить эту проверку нельзя.
