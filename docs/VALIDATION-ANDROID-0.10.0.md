# Проверки SorryRKN 0.10.0

## Что воспроизведено и исправлено

- Старая реализация отклоняла семь из восьми одновременных TCP-подключений к работающему дата-центру Telegram. Также пустой пул немедленно возвращал отказ клиенту, хотя через 10 мс были готовы четыре WSS-соединения. Исправлены ожидание пула и обработка параллельных подключений.
- Полный тест старого пула падает на первом всплеске загрузок. Новый проходит с настоящим MTProto init, AES-CTR, тремя форматами транспортных кадров, маскированным WebSocket, TLS и фрагментацией.
- Выявлен неподтверждённый путь CDN203 → обычный WSS DC2. В итоговой версии WSS разрешён автоматически только для DC1–5; CDN203 использует native TCP. Тестовый сервер специально отвергает ошибочное направление CDN203 в WSS.
- Нейросети раньше обходили локальный движок DPI и подключались непосредственно к адресам Comss. Теперь Android всегда передаёт `own_ip:true`, использует обычный DoH и локальный ByeDPI для выбранных имён.

## Проверки

- **295 Python-тестов и 32 подтеста прошли.** Проверяются DNS, настоящий native ByeDPI, проверка TLS/SNI, прямые исключения, отсутствие Comss в режиме своего IP, очереди, отмена, завершение и освобождение проигравших соединений, медиатаймеры и уже существующие функции.
- Android API 26 x86_64, эмулятор без аппаратного ускорения: **12 одновременных клиентов**, включая 8 медиа при размере пула 2; **17 008 292 байта**, 41 запрос, DC1–5 и CDN203. Содержимое побайтно сверено. Передаётся транспортная ошибка `-404`, затем новое подключение снова получает данные. Для начальных соединений используется барьер перед массовой загрузкой, чтобы вычисления тестового сервера на том же эмуляторе не занимали время подключения; производственные таймауты сохранены.
- Telegram через упакованный Android ByeDPI: настоящие локальный SOCKS, TLS с проверкой имени `kws4-1.web.telegram.org`, WebSocket и двусторонняя передача бинарных данных, UTF-8 эмодзи и 1 MiB. Проверяется отсутствие CF/H2/worker-реле. Тестовый сервер находится на стенде; это проверка сетевого пути APK, а не загрузка из пользовательского аккаунта Telegram.
- Отдельный UID Android: настоящий TUN, TCP 128 KiB, UDP 1000 байт, восемь HTTPS-имён по 1 MiB и Discord WebSocket Hello. Проверяются раздельные методы YouTube/Discord, AI и Instagram, `own_ip:true`, отсутствие Comss и нулевые попытки старого geo-relay.
- Android: сохранение пользовательских правил, приоритет исключения, режим только с пользовательскими доменами, диалог обновления при запуске и возвращении после HOME. Установка поверх 0.9.4 с прежней подписью прошла.
- ChatGPT: 22 проверки публичного запроса, включая реальные локальные SOCKS/TLS, отклонение неверного сертификата, таймаут, отмену, ограничение тела 32 KiB и осторожное распознавание регионального отказа/Cloudflare challenge. Во всех результатах `authenticated_access:false`.
- Сборка APK/test APK и lint успешны: 0 ошибок, 3 прежних предупреждения. Все включённые Python-модули APK сверены с исходниками; подпись и zipalign 16 KiB проверены.
- APK: `dev.graybridge`, versionCode 14, Android 8.0+, ARM64/x86_64. SHA-256 сертификата: `854ef7e3cbfdb5fc624bc3ec7b7d9e17780b709bac7fb85b77dbf4ea0acf2ef4`.

## Пределы проверки

Стенд не имеет доступа к телефону Samsung, сетям Yota/Indikom, аккаунтам Telegram и ChatGPT. Внешние HTTP/HTTPS доступны через прокси окружения, внешний raw TCP — нет. DNS и отказы сверяются отдельно; загрузки и TLS-передачи используют настоящие локальные сокеты и тестовые сертификаты. Тестовые CA/ключи не входят в пользовательский APK. Скорость эмулятора не является замером скорости телефона или оператора.

Проверены исправленные механизмы, а не постоянная доступность всех сервисов. Локальный DPI не устраняет запрет сервиса по стране исходного IP. Россия отсутствует в [списке поддерживаемых стран ChatGPT](https://help.openai.com/en/articles/7947663-chatgpt-supported-countries). Прямой CDN Telegram также зависит от доступности его IP; неизвестные будущие DC не получают выдуманных маршрутов.

Источники для CDN: [Telegram CDN](https://core.telegram.org/cdn), [официальный MTProxy](https://github.com/TelegramMessenger/MTProxy), [Telegram Android](https://github.com/DrKLO/Telegram). Параметры getProxyConfig относятся к RPC-протоколу MTProxy и не подставляются в обычный native TCP.
