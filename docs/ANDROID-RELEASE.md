# Выпуск нового Android-приложения

С Android 1.0.0 используется пакет `io.github.def01d.sorryrkn`. Постоянный производственный сертификат SHA-256 — `62d06753eab97aa19304d8adcdcdcf6bf5fe4e72e58336dd7085de4236880f1f`. Публичные сведения находятся в [android/signing-identity.json](../android/signing-identity.json).

Приложение устанавливается вручную один раз. Последующие версии предлагаются при каждом запуске и устанавливаются после подтверждения Android. Канал — [android-update.json](../android-update.json). Проверяются подпись манифеста, размер и SHA-256 APK, имя пакета, версия и совпадение сертификата установленного приложения.

Новый пакет устанавливается отдельно от прежнего `dev.graybridge`. Настройки старого приложения автоматически не переносятся. Перед включением новой версии выключите старое VPN-соединение и заново добавьте её Telegram-прокси. Прежние теги, APK и канал `update.json` сохранены как история.

## Подпись

Ключ хранится вне Git. Основной пароль защищён Windows DPAPI текущего пользователя. `tools/Sign-AndroidRelease.ps1` передаёт пароль инструментам через stdin и переменную окружения дочернего процесса, без пароля в аргументах команды. Хранилище ключа и комплект восстановления лежат в папках с доступом только владельца и SYSTEM.

Комплект восстановления содержит `signing.keystore`, публичный `identity.json` и **секретный `recovery.json` с паролем**. Его нужно держать закрытым и сохранить отдельную офлайн-копию. В GitHub, архив исходников, логи и канал обновлений комплект не включается. Повторная генерация ключа для этого пакета запрещена — восстанавливайте существующий ключ.

В комплекте также сохранён `update-manifests.key-backup.json` — зашифрованная AES-GCM копия независимого ключа подписи манифестов. Пароль для её восстановления тот же, что в закрытом `recovery.json`; восстановление выполняется через `tools/Update-Signing.ps1 -Action Restore`. Проверены восстановление обоих ключей, совпадение сертификата APK и сохранение прежнего открытого ключа манифестов. Для полного восстановления выпуска нужны оба ключа.

CI создаёт проверенный неподписанный входной APK в артефакте `android-unsigned-release`. Для производственной подписи:

```powershell
./tools/Sign-AndroidRelease.ps1 -InputApk unsigned.apk -OutputApk SorryRKN-Android-VERSION.apk
```

Для восстановления из закрытого комплекта, включая другой профиль Windows:

```powershell
./tools/Sign-AndroidRelease.ps1 -UseRecoveryBackup -BackupDirectory PRIVATE_RECOVERY_FOLDER -InputApk unsigned.apk -OutputApk restored.apk
```

После подписи обязательно сверяйте сертификат с публичным отпечатком. В штатном инструменте это проверяется автоматически. Для Android нужен настроенный WSL, JDK 17 и Android build-tools 35.0.0; пути задаются параметрами инструмента.

## Публикация и проверки

Увеличьте `versionCode` и `versionName`, дождитесь CI, подпишите его APK постоянным ключом. На отдельном эмуляторе проверьте установку, обновление поверх предыдущей версии и сохранение настроек, Telegram-секрета и AndroidKeyStore-хранилища. Тесты `ProductionUpdateChecks` также отклоняют APK другого подписанта и проверяют настоящие предложение и загрузку обновления.

Опубликуйте APK в новом неизменяемом теге `android-vVERSION` по пути `android/SorryRKN-Android-VERSION.apk`. Скачайте точный tagged raw URL, проверьте размер, SHA-256 и сертификат. Затем создайте обычный публичный релиз и активируйте подписанный `android-update.json` через `tools/Update-Signing.ps1`. Ключ манифестов обновления и ключ подписи APK независимы. Неподписанные, тестовые APK и временные базовые версии в производственный канал не публикуются.
