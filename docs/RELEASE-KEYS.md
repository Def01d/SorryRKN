# Ключи и выпуск обновлений

## Android APK

Обычная установка `dev.graybridge` требует исходный ключ APK с SHA-256 сертификата `854ef7e3cbfdb5fc624bc3ec7b7d9e17780b709bac7fb85b77dbf4ea0acf2ef4`. Новый ключ не обеспечивает обновление поверх прежнего приложения. Неподписанные и `.dev` APK не используются в основном канале.

В доступной восстановленной облачной среде исходный ключ не найден. Проверены прежние каталоги, доступные архивы и артефакты; наличие внутреннего снимка платформы установить нельзя. Возможный следующий шаг — запросить у поддержки восстановление файловой системы облачного чата на 10 октября 2026 года около 12:13 МСК. Частный ключ нельзя получить из подписанного APK.

## Подписи манифестов приложения и каталога DNS

Это отдельный ключ ECDSA P-256. Открытая часть хранится в `update-trust.json` и включена в приложения. Закрытая часть находится вне репозитория, в профиле сопровождающего, и зашифрована Windows DPAPI для текущего пользователя. Она не передаётся в GitHub Actions. Пароли и ключи не публикуются.

Средство `tools/Update-Signing.ps1` требует PowerShell 7.4+. Подписанный JSON сохраняет плоские поля для старых клиентов; новые клиенты используют проверенное содержимое `signed`. Подпись связывает payload, ключ, время выпуска и срок действия. Старые клиенты не получают защиту подписи до установки новой версии. Это не полная реализация TUF и не система ротации доверенных ключей.

Подпись подготовленного манифеста:

```powershell
pwsh -File tools/Update-Signing.ps1 -Action Sign -ManifestPath windows-update.json
```

Подписывать новый канал можно после публикации и независимой проверки точного файла по неизменяемому тегу. Метаданные указывают размер и SHA-256. Новый выпуск является обычным релизом, не prerelease.

## Переносимая резервная копия

DPAPI привязывает локальный файл к Windows-профилю. Для восстановления на другом компьютере нужна отдельная зашифрованная копия и её пароль. Следующие команды запускает владелец в своём терминале; пароль вводится скрыто и не передаётся в чат:

```powershell
pwsh -File tools/Update-Signing.ps1 -Action Backup -BackupPath 'D:/PrivateBackup/sorryrkn-updates.key-backup.json'
```

После восстановления исходников и открытого `update-trust.json` на новом компьютере:

```powershell
pwsh -File tools/Update-Signing.ps1 -Action Restore -BackupPath 'D:/PrivateBackup/sorryrkn-updates.key-backup.json'
```

Копия использует PBKDF2-SHA256 и AES-256-GCM. Восстановление проверяет совпадение открытого ключа приложения, прежде чем сохранять ключ под новым DPAPI-профилем. Существующие ключи не перезаписываются. Храните копию и пароль раздельно; переносимая резервная копия не создаётся автоматически.
