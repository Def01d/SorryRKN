# Android 0.13.0: готовый вход для подписи

APK **не подписан** и предназначен только для восстановления обычного выпуска. Основной канал остаётся на подписанной 0.11.0. Нельзя устанавливать этот файл или пакет `.dev` как обычное обновление.

- Пакет `dev.graybridge`, версия `0.13.0`, code `20`, minSdk `26`, ARM64 / x86_64.
- Размер **20094559 байт**.
- SHA-256: `7265991ae6620313eda1ce0bafab24273836ded14b4be3550c61532a3a82a43e`.
- [Git blob входного APK](https://api.github.com/repos/Def01d/SorryRKN/git/blobs/8b3f0b2398a6f26228013a790938e0b19e7dca2f); `content` — Base64, blob SHA `8b3f0b2398a6f26228013a790938e0b19e7dca2f`.
- Содержимое ZIP и выравнивание 16 KiB проверены. Debug/instrumentation сборки прошли проверки в API 35 x86_64; production-обновление без прежнего ключа не проверено.

После восстановления исходного keystore подписать **точный входной APK без пересборки**. Требуемый SHA-256 сертификата: `854ef7e3cbfdb5fc624bc3ec7b7d9e17780b709bac7fb85b77dbf4ea0acf2ef4`. Новый ключ не подходит для установленной основной версии.

Проверить apksigner, `zipalign -c -P 16 -v 4`, пакет/версию и неизменность исходных ZIP entries. Проверить установку поверх 0.11.0 с синтетическими настройками и сохранением UID/секрета. Ключ и пароли не выводить, не публиковать и не передавать.

Подписанный результат и очищенный отчёт передать как Git blobs, сообщив SHA blob, размер и SHA-256. Исполнитель подписи не меняет main/теги/релизы/каналы обновлений. Публикующий исполнитель проверяет результат независимо, создаёт обычный `v0.13.0`, проверяет точный APK по тегу и только затем подписывает/активирует новый `update.json`.

Подпись APK и ключ подписей JSON — разные ключи. Подробнее: [RELEASE-KEYS.md](RELEASE-KEYS.md).
