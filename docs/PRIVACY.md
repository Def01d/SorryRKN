# Трафик и локальные данные

[← Главная](../README.md) · [Помощь](FAQ.md)

## Как обрабатывается соединение

**Android 0.11.0 и Windows 1.2.0:** для нейросетей доступен внешний маршрут через DNS-профиль Comss, а для Telegram — проверяемые прямые маршруты и запасные внешние реле. В Android оба внешних режима разрешены по умолчанию и отдельно отключаются в меню «Маршруты». IP выбранных сервисов может меняться; обычный HTTPS проверяет сертификат и имя сервера. Служебные проверки используют анонимные запросы и не входят в аккаунты. [Настройки Android](ANDROID.md) · [Проверки Windows](../windows/src/VALIDATION.md).

На Android SorryRKN использует локальный VPN для передачи трафика в движки на устройстве; на Windows — winws и WinDivert. У проекта нет общего зарубежного VPN-сервера, через который направляется весь трафик. Приложение не предоставляет анонимность или зарубежный IP всем программам.

Telegram-прокси слушает только `127.0.0.1:1443`. В Android 0.11.0 и Windows 1.2.0 прямые WSS/native TCP-подключения и запасные внешние маршруты выбираются по ответу MTProto; прежний HTTP2-путь не используется для рабочего трафика. Выбор выполняется отдельными служебными запросами: пользовательские запросы не рассылаются нескольким кандидатам и не повторяются после начала отправки. На Android внешнее реле Telegram можно отдельно запретить в меню «Маршруты». Условия и доступность внешних сетевых сервисов определяются их провайдерами.

В Android 0.10.0 Comss-реле были отключены. В 0.11.0 они разрешены по умолчанию для нейросетей и первого списка «Моих ресурсов»; режим со своим IP включается отключением «Зарубежного реле для нейросетей». Instagram, YouTube и Discord используют локальный обход DPI. Windows 1.2.0 использует Comss DNS для выбранных доменов нейросетей и пользовательского DNS-профиля. Прямые исключения имеют приоритет на обеих платформах.

На Android для обычного DNS используются публичные DoH-провайдеры, включая Cloudflare, Google и Quad9. При активном DNS-перехвате Windows 1.2.0 разрешает защищаемые домены YouTube, Discord, Instagram и Telegram через Google/Cloudflare DoH, остальные запросы и прямые исключения оставляет прежнему DNS. DNS-провайдер получает запрашиваемые имена и сетевые метаданные в соответствии со своими правилами.

Устанавливать сертификат перехвата TLS не требуется. Обычные HTTPS/WSS-подключения проверяют доверенную цепочку сертификатов и соответствие имени сервера.

Начиная с Android 0.10.1 есть ограниченное исключение для прежнего совместимого Telegram-маршрута: адрес назначения строго `149.154.167.220`, HTTP Host — `kws2.web.telegram.org`, `kws2-1.web.telegram.org`, `kws4.web.telegram.org` или `kws4-1.web.telegram.org`, маскирующий SNI — `sprinthost.ru`. Здесь цепочка TLS по-прежнему проверяется, но проверка имени сертификата отключена. Это слабее обычной проверки TLS; исключение не распространяется на другие адреса, домены, DNS, ChatGPT или обновления. Данные идут прямо на закреплённый адрес Telegram, а имя SNI не означает подключения к серверу этого сайта. Android 0.11.0 сохраняет это ограниченное исключение.

В Windows 1.2.0 совместимый WSS-маршрут Telegram с маскирующим SNI также проверяет цепочку сертификатов без проверки имени. Обычные WSS-подключения и HTTPS для DNS, нейросетей и обновлений используют проверку имени сервера.

## Что хранится на устройстве

- Настройки сервисов и выбранный метод.
- Пользовательские домены обхода и прямых исключений; обновления GitHub их не заменяют.
- Секрет локального Telegram-прокси.
- Снимки данных обхода и Telegram-доменов.
- Результаты проверок, технические журналы и счётчики трафика.

Windows хранит эти файлы в `%LOCALAPPDATA%\SorryRKN`; секрет защищён Windows DPAPI под текущим пользователем. На Android настройки и секрет находятся в приватных данных приложения. Удаление приложения Android или очистка его данных сбрасывает настройки; удаление Windows сохраняет их для переустановки.

Установка обычного APK 0.11.0 с прежней подписью поверх `dev.graybridge` сохраняет настройки и секрет. SorryRKN Test (`dev.graybridge.dev`) хранит отдельные данные и этим APK не обновляется; автоматического переноса его настроек в основное приложение нет.

## Диагностика и обращения

Штатный диагностический отчёт не содержит секрета Telegram. В нём могут быть модель устройства, версия системы, оператор или характеристики сети, результаты проверок и метаданные соединений.

Начиная с Android 0.10.2 раздел `telegram_routes` хранит ограниченную историю исходящих этапов: имя и IP сервера назначения, порт, маршрут, этап, время, результат, класс исключения и разрешённые числовые коды ошибки. Также отображаются активные попытки, счётчики и паузы до повтора. История этапов ограничена 64 записями; списки активных попыток и пауз также ограничены. Счётчики Telegram и история относятся к текущему включению соединения и сбрасываются при следующем запуске. Текст исключения, HTTP-заголовки и тело ответа, секреты, сообщения и файлы в эту историю не записываются.

Раздел `telegram_tls` содержит только сведения о локальной библиотеке TLS и её настройках: версию OpenSSL, число доверенных CA, обязательность проверки цепочки и имени. Он не содержит сертификатов, ключей или содержимого соединения и не подтверждает сертификат удалённого сервера.

При включённом профиле нейросетей Android периодически проверяет публичную страницу ChatGPT через локальный маршрут. Внешние адреса ChatGPT дополнительно проверяются отдельными HTTPS-запросами к публичному `/api/auth/providers`, чтобы предпочесть отвечающее реле. Windows 1.2.0 также использует этот публичный API для выбора и проверки маршрута. Аккаунт, cookies и сообщения пользователя не используются, существующие пользовательские соединения не переключаются. В отчёт записываются выбранный адрес назначения, стадия, HTTP-статус и классификация ответа, без тела страницы и исходного IP пользователя. Успешный ответ не подтверждает вход или отправку сообщения.

При включённом Telegram Android 0.11.0 отправляет через локальный прокси отдельные начальные MTProto-запросы `req_pq_multi` в DC1–DC5. Проверяется структура ответа `resPQ` и совпадение случайного `nonce`. Если ответили все пять DC, проверка повторяется через 120 секунд; если ответили не все — через 30 секунд. Учётные данные, сессия Telegram, сообщения и файлы пользователя не используются; проверка не входит в аккаунт и не закрывает рабочие соединения. В диагностике хранится технический результат в `telegram_check`.

Автоматическая отправка диагностического отчёта в issue не выполняется: пользователь сам копирует или прикладывает его. GitHub Issues публичны. Просматривайте отчёт и журналы перед публикацией, не прикладывайте ссылки на локальный прокси, пароли и личные переписки.

## Обновления

Начиная с 0.9.4 Android проверяет манифест APK при каждом открытии приложения и возвращении на его экран. Скачивание начинается после подтверждения пользователя.

Windows проверяет манифест своей платформы при запуске, если после последней успешной проверки прошло больше шести часов. Ручная команда обновления на обеих платформах проверяет сразу.

При проверке программа обращается к GitHub за манифестом своей платформы и к исходным проектам за совместимыми данными. GitHub видит обычные метаданные HTTPS-запросов. Установочные файлы проверяются по размеру и SHA-256; Android дополнительно проверяет пакет, версию и подпись APK.

Новые возможности бинарных движков распространяются с новой версией программы. Windows-обновление данных не запускает скачанные BAT/CMD, не заменяет DLL/EXE и не исполняет новый Python-код.
