# Проверки SorryRKN 0.9.4

- Python: **238 passed, 32 subtests passed**, включая 11 новых проверок DNS-профиля и безопасного перехода на запасной адрес.
- Воспроизведение на 0.9.3: локальный первый DNS-адрес принимает ClientHello, но не отвечает; второй адрес обслуживает HTTPS. Старая версия не обращается ко второму адресу, TLS-запрос завершается ошибкой. На 0.9.4 тот же запрос проходит.
- Настоящие локальные TCP/TLS соединения: первый адрес молчит, возвращает fatal TLS alert или отклоняет подключение; второй отвечает сертификатом для `chatgpt.com`. Два HTTPS-запроса проходят с исходным SNI, проверкой сертификата и без повторения HTTP-запроса. Сбойный адрес получает меньший приоритет для следующего подключения.
- Дополнительная проверка с производственными таймаутами: молчащий первый адрес освобождается за три секунды; запрос через запасной адрес завершается до пятисекундного таймаута клиента. Неверный сертификат по-прежнему отвергается. 0-RTT данные не отправляются повторно; отмена освобождает сокет без отметки адреса как сбойного.
- HTTPS-запросы к актуальному Comss DoH подтвердили по два A-адреса для `chatgpt.com`, `chat.openai.com`, `api.openai.com`, `android.chat.openai.com`, `auth.openai.com`, `cdn.oaistatic.com`. Проверялись DNS-ответы, а не вход в реальный аккаунт ChatGPT.
- Android API 26 x86_64, эмулятор: новая версия предлагается при открытии, несмотря на недавнюю проверку. После HOME и повторного открытия запрос выполняется снова. При пересоздании Activity незавершённая проверка передаёт предложение новому экрану без дополнительного HTTP-запроса. Проверены отключение HTTP-кеша и настоящий диалог обновления; перехват HTTPS существует только в отдельном тестовом APK.
- Android VPN, отдельный UID: TCP 128 KiB, UDP 1000 байт, восемь HTTPS-доменов по 1 MiB с проверкой сертификатов, WebSocket Discord Hello. Проверены разные методы YouTube/Discord, маршруты ChatGPT/Claude/Gemini, Instagram и прямого сайта, подавление AAAA/HTTPS DNS-профиля. Сокеты и сертификат тестового сервера локальные; DNS и результаты подбора задаются тестом, поскольку внешние raw TCP стенда недоступны.
- Android: редактор пользовательских правил, отказ при неверном вводе, нормализация, сохранение настроек, приоритет прямого исключения и запуск режима только с пользовательским DNS-профилем.
- Все проверки восстановления Telegram из 0.9.3 входят в Python-набор; его модули в APK сверены с исходниками. Telegram-транспорт в этом обновлении не менялся.
- Gradle assembleDebug/assembleDebugAndroidTest/lintDebug: успешно; lint — 0 ошибок, 3 прежних предупреждения.
- APK: `dev.graybridge`, versionCode 13, minSdk 26, arm64-v8a + x86_64. Подписант прежний: `854ef7e3cbfdb5fc624bc3ec7b7d9e17780b709bac7fb85b77dbf4ea0acf2ef4`. Проверка подписи и zipalign 16 KiB прошли; установка поверх 0.9.3 успешна.
