# SorryRKN для Android — исходники

Исходники Android-приложения версии **0.11.0**: интерфейс Java, локальный
`VpnService`, Python-маршрутизация и MTProto-прокси, а также нативные движки
ByeDPI, tpws и hev-socks5-tunnel. Изменения версии перечислены в
[CHANGELOG.md](CHANGELOG.md).

## Обновление установленного приложения

Обычный [APK 0.11.0](https://github.com/Def01d/SorryRKN/releases/tag/v0.11.0)
сохраняет пакет `dev.graybridge` и подпись прежних релизов. Он устанавливается
поверх основной версии с сохранением настроек и Telegram-секрета и предлагается
встроенным обновлением. Android запрашивает подтверждение скачивания и установки.
Отдельный пакет `dev.graybridge.dev` (**SorryRKN Test**) предназначен для разработки;
его настройки не переносятся в основное приложение автоматически.

## Подключение и маршруты

При новой установке включены обход DPI, Telegram, нейросети и Instagram.
Сохранённые настройки предыдущей установки сохраняются. После включения нажмите
«Подключить Telegram» и подтвердите добавление локального прокси в Telegram.

Меню **«Маршруты»** задаёт два независимых режима:

| Настройка | Включена по умолчанию | Если выключить |
| --- | --- | --- |
| Зарубежное реле для нейросетей | Для ChatGPT, Claude, Gemini и списка «Мои ресурсы» используется внешний маршрут через DNS-профиль Comss | Локальный обход DPI со своим IP; ограничения страны на стороне сервиса остаются |
| Запасное реле Telegram | Внешние реле доступны как запасной путь, если прямые маршруты не отвечают | Только прямые подключения к серверам Telegram |

YouTube, Discord и Instagram используют локальный обход DPI. Прямые исключения
из «Моих ресурсов» имеют приоритет для сайтов. Сохранение изменённых маршрутов
перезапускает активное подключение. Переключатели самих сервисов меняются при
выключенном подключении.

Android показывает значок VPN, поскольку приложение перехватывает трафик на
устройстве. Это не означает, что весь трафик идёт через один внешний VPN-сервер.
При включённом реле IP выбранных сервисов может отличаться от IP пользователя;
доступ зависит от внешнего реле и правил самого сервиса. При выключенном реле
обход DPI сам по себе не меняет страну исходящего IP. HTTPS остаётся соединением
клиентского приложения или браузера с запрошенным сайтом.

Автоматический подбор начинает с ранее сохранённого метода для текущей сети и
основных стратегий. Если быстрые варианты не помогают, поиск автоматически
переходит к оставшемуся каталогу в пределах общего времени подбора. Рабочие
маршруты YouTube и Discord сохраняются отдельно; частичный успех одного сервиса
не выключает уже доступный другой. Смена физической сети запускает повторный
подбор, а не переносит результат одной Wi-Fi-сети на все остальные.

Для Telegram выбирается маршрут, ответивший на настоящий запрос MTProto с
проверкой случайного идентификатора. Открытого TCP-порта или WebSocket недостаточно.
Проверка маршрутов использует собственные служебные запросы; пользовательский
пакет не рассылается по нескольким маршрутам и не повторяется при сбое.

## Что показывает диагностика

- Telegram: ответы DC1–DC5, число ответивших дата-центров и наименьшая задержка.
  Фоновая проверка не входит в аккаунт и не подтверждает передачу медиа.
- ChatGPT: ответ публичной страницы, региональный отказ, проверка браузера или
  ошибка соединения. Ответ страницы не подтверждает вход и отправку сообщения.
- YouTube и Discord: DNS, тестовые HTTP-ответы, Discord Gateway Hello и CDN.
  Эти проверки не подтверждают воспроизведение всех видео или голос Discord.
- «Включено» означает, что сетевые модули запущены. «Частичный доступ» и карточки
  сервисов показывают обнаруженные отказы; ручная стратегия отмечена как
  непроверенная. Отчёт в меню содержит этапы отказов и выбранные маршруты.

Доступность в одной сети не доказывает доступность у другого оператора. Проверка
внешних сервисов без пользовательского аккаунта также не заменяет проверку
сообщений, входа и медиа на устройстве.

## Сборка APK

Среда сборки — Linux x86_64. В Windows используйте WSL2 с Linux-версией
Android SDK. Скрипт нативной сборки требует Bash и не рассчитан на запуск из
обычного Windows CMD/PowerShell.

Понадобятся:

- JDK 17 и Python 3.12 в `PATH`;
- Android SDK Platform 35, Build Tools 35.0.0 и Platform Tools;
- Android NDK **28.2.13676358**;
- интернет для первоначальной загрузки Gradle, Android Gradle Plugin и пакетов
  Chaquopy/Python.

Из этой папки, содержащей `gradlew` и `settings.gradle`:

```bash
export ANDROID_HOME="$HOME/Android/Sdk"
export PATH="$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$PATH"
sdkmanager "platform-tools" "platforms;android-35" "build-tools;35.0.0" "ndk;28.2.13676358"
sdkmanager --licenses
./gradlew :app:assembleDebug
```

Если SDK установлен в другом месте, измените `ANDROID_HOME`. В Android Studio
можно открыть эту папку как Gradle-проект и выбрать JDK 17; IDE создаст локальный
`local.properties`, который не следует коммитить.

Результат: `app/build/outputs/apk/debug/app-debug.apk`.

```bash
adb install app/build/outputs/apk/debug/app-debug.apk
```

Debug-сборка называется **SorryRKN Test**, имеет `applicationId`
**`dev.graybridge.dev`** и использует локальный отладочный ключ Android. Она
устанавливается рядом с основной версией, хранит отдельные настройки и не заменяет
её. Android позволяет работать только одному VPN одновременно.

`./gradlew :app:assembleRelease` создаёт **неподписанный** release APK
`app/build/outputs/apk/release/app-release-unsigned.apk` с исходным
`applicationId` **`dev.graybridge`**. Приватного ключа установленной авторской
сборки в исходниках нет. APK с другим ключом не может обновить её поверх
существующей установки. Для совместимого обновления требуется тот же ключ;
для самостоятельной публикации используйте собственный ключ, храня ключ и пароли
вне репозитория. Конфигурация проекта не обращается к закрытому release-keystore.

Нативные `.so` не включены в исходники: задача `buildNative` автоматически собирает
их из `native/` и `third_party/` для `arm64-v8a` и `x86_64`. Минимальная версия
Android — 8.0/API 26. Корректировки линковки для страниц 16 КБ находятся в
`native/` и `scripts/build-native.sh`.

## Проверка на компьютере

Для локальных сетевых тестов нужны Python 3.12, C-компилятор, Make и заголовки
zlib/libcap. В Debian/Ubuntu установите `build-essential`, `zlib1g-dev` и
`libcap-dev` (последний предоставляет `sys/capability.h` для Linux-версии tpws).

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
source .venv/bin/activate
bash scripts/test-network.sh
```

Скрипт собирает отдельные тестовые tpws/ByeDPI и запускает `pytest`. Разрешение
локальных адресов в тестовом tpws применяется только к временной копии исходника
и не входит в APK. Стендовые проверки проверяют протоколы, конкурентные соединения
и очистку ресурсов; они не доказывают доступность сервисов в конкретной сети.

Android-инструментальные проверки находятся в `app/src/androidTest/`;
`tests/device-probe/` — вспомогательное приложение с отдельным UID. Для сборки:

```bash
./gradlew :app:assembleDebugAndroidTest :device-probe:assembleDebug
```

Часть инструментальных сценариев требует локальных серверов из `tests/` и
параметров тестового runner; это инструменты разработки, а не автоматическая
проверка оператора связи.

Для `tests/telegram_dpi_server.py` и `tests/telegram_fronting_server.py` явно
передавайте `--fixture-dir` с отдельной локальной папкой для тестовых сертификатов.
Созданный там `key.pem` не должен попадать в репозиторий или APK.

## Состав и зависимости

- `app/src/main/java/` — Android UI, сервис и плитка быстрых настроек.
- `app/src/main/python/` — маршрутизация, DNS и Telegram-прокси.
- `app/src/main/assets/` — стартовые данные и тексты лицензий.
- `native/`, `third_party/` — JNI и полные нативные зависимости для сборки.
- `tests/`, `app/src/androidTest/` — тесты и локальные серверы.
- `docs/upstream-lock.json`, `docs/hev-submodules.txt` — версии исходных проектов.
- [THIRD_PARTY.md](THIRD_PARTY.md) — происхождение и лицензии компонентов.

HEV-зависимости уже включены обычными файлами: `git submodule update` не требуется.
Их внутренние символьные ссылки заголовков представлены содержимым соответствующих
файлов, чтобы исходники работали и после загрузки ZIP. Перечень преобразований —
`docs/export-symlinks.json`.

Версии сборки зафиксированы в Gradle: Gradle 8.13, Android Gradle Plugin 8.9.2,
Chaquopy 17.0.0, Python 3.12; Python runtime устанавливает
`httpx[http2,socks]==0.28.1` и `certifi==2026.2.25`.

Собственный код распространяется под [MIT](LICENSE). Лицензии сторонних файлов
продолжают действовать отдельно. Кеши, APK, готовые нативные бинарники, `local.properties`,
ключи подписи и локальные Git-каталоги в этот экспорт не включены.
