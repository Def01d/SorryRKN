## Автоматические и сетевые проверки

- **414 Python-тестов и 28 дополнительных проверок прошли** на Linux / Python 3.12. Проверяются реальные локальные TCP, SOCKS, TLS, UDP и WebSocket-соединения, криптографические потоки, таймауты, отмена, прямые исключения и маршрутизация.
- Проверки протокола Telegram не повторяют пользовательские пакеты: маршрут выбирается отдельным запросом с новым nonce и проверкой структуры `resPQ`.
- Живой Android Python-прокси на компьютере: **10/10** DC1–5, обычные и media-маршруты, 184–991 мс.
- Живой Linux Gateway с настоящим ByeDPI: YouTube 204 и изображение CDN, Discord API/CDN/WebSocket Hello, Instagram, Telegram Web, страница ChatGPT и OAuth providers — успешные ответы. Селектор ChatGPT исключил два адреса с 403 challenge и выбрал адрес с корректным ответом 200. Это результат одного прогона, а не обещание постоянной доступности публичного реле.

## Собранный APK: Android 15, эмулятор x86_64

- Реальный сервис, Android Java AES и локальный Telegram-прокси: **10/10** ответов DC1–5, main/media, 340–2305 мс. Сервис остался включён во время проверки; после теста процесс движка и порты закрылись.
- Реальные официальные WSS DC2/DC4 через нативный ByeDPI: **2/2**, 304 и 460 мс, цепочка сертификатов и имя узла проверены. Это не проверка запасного legacy-fronting пути.
- Жизненный цикл: запуск/остановка tpws, адаптивного ByeDPI, VPN и Telegram; отмена автоподбора; освобождение портов; NIST AES-CTR на несогласованных границах блоков — PASS.
- Отдельное приложение с другим UID действительно использовало Android VPN: TCP 128 КиБ, UDP 1000 байт, HTTPS по восьми доменным именам по 1 МиБ с проверкой содержимого и сертификатов, Discord WebSocket Hello, DNS AAAA/HTTPS — PASS.
- Этот тест прошёл в трёх режимах: ByeDPI, разные методы для YouTube/Discord, только дополнительные сайты. Проверены счётчики TUN и маршрутов. Серверы этого теста локальные, с отдельным тестовым CA; он не устанавливался в системное хранилище доверия.

## Публичные сервисы через Android VPN

Отдельное приложение с другим UID использовало системный DNS Android и настоящий
VPN-интерфейс собранного APK. Автоподбор, все три сервиса и внешние маршруты были
включены. Все TLS-подключения проверяли системную цепочку доверия и имя сервера.
Один прогон: **7/7**, общая длительность запросов 2296 мс.

| YouTube generate_204 | HTTP 204 | 1768 мс |
| Discord API gateway | HTTP 200, структура JSON | 1570 мс |
| Discord CDN | HTTP 200, PNG | 1546 мс |
| Discord Gateway | HTTP 101, WebSocket Hello | 1661 мс |

Python-проверка при старте получила Cloudflare challenge от адресов Comss,
но отдельный Android TLS-клиент через VPN получил корректные ответы ChatGPT.
Это показывает зависимость результата от клиента и времени проверки: статус
служебной проверки нельзя считать доказательством отказа браузера. Во время
прогона использовался внешний маршрут; последний адрес реле в диагностике —
`157.22.177.90`. В аккаунты не входили, cookies и сообщения не отправляли.
После теста сервис остановлен, порты освобождены, настройки восстановлены.

## Границы результата

- Эмулятор использует сеть компьютера. Физические телефоны, ARM64 во время исполнения и сети всех российских операторов не проверены.
- Проверка media DC подтверждает протокольный маршрут, а не скачивание файлов из аккаунта. Переписка, звонки, авторизованный ChatGPT, вход в Instagram и воспроизведение YouTube не проверялись.
- Публичные реле могут перестать отвечать или получить отказ от сервиса. Cloudflare challenge требует отдельной проверки в браузере; приложение показывает это состояние. Обход DPI не снимает все ограничения по IP и региону.
- Прямой режим доступен отдельно в меню «Маршруты». При его выборе исходный IP сохраняется, поэтому региональный отказ может остаться.

## Повторение

См. команды сборки в `README.md`. Python: `bash scripts/test-network.sh`.
Живая диагностика шлюза: `PYTHONPATH=app/src/main/python .venv/bin/python tests/live_network_check.py --byedpi build/test-byedpi`.
На тестовом устройстве с установленными APK приложения и instrumentation:

```sh
adb shell am instrument -w -e telegramVerifiedChecks true dev.graybridge.dev.test/dev.graybridge.DeviceChecks
adb shell am instrument -w -e publicServiceChecks true dev.graybridge.dev.test/dev.graybridge.DeviceChecks
```

Отчёты поставляются рядом с APK в каталоге `validation/android`. Они не содержат токенов аккаунтов или переписки.
